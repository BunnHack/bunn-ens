## GEFS / AIGEFS workflow-generated charts

`.github/workflows/ncep-ensembles.yml` publishes actual **GEFS +0–120h** and **AIGEFS +0–240h**, each **31 members: control 0 and perturbed 1–30**, on the separate `ensemble-track-data` branch. The deterministic **AIGFS (L)** product above is not AIGEFS and is not counted as a member. Native tracker `VMAX` stays kt and MSLP stays hPa: keep the **34-kt radius rows**, not only storms with VMAX ≥34kt; ignore provider mean files and deduplicate repeated quadrants. GEFS's different genesis format retains its native TG/HC/basin category, original token, storm counter and member; a candidate is not automatically a tropical cyclone. Only clearly duplicate same-member, multi-UTC native genesis paths are omitted, never spliced into another track.

AIGEFS has no equivalent published genesis directory. Its additional **local field-L** branch validates each member's native MSLP / 10m U/V GRIB headers, units, 0.25° grid, exact initialization, member, lead and valid UTC. L search is restricted to ±45° latitude, births to ±35°, ≤1012hPa and ≥0.5hPa closure at 250km. Track at real 6h steps with ≤510km motion; ambiguous/shared lows, missing fields or disappearance stop the path. Initial Ls are not newly generated storms. At least two consecutive fixes are required. Actual local 10m vector speed is retained separately in **m/s**, never substituted for tracker VMAX, pressure-derived wind or evidence of tropical structure. Partial native/genesis/field coverage keeps the declared denominator 31 and is disclosed.

**Direct image generation:** `.github/workflows/ncep-charts.yml` runs after a successful source workflow or manual dispatch. It pins one exact public data commit, renders seven basin maps and separate numbered-system **member tracks / conditional mean / wind / pressure PNG + standalone SVG**, and publishes only small source JSON/CSV with them. Position and intensity means are separate, require **≥8/31 reporting members**, and never average unrelated storms or genesis/L candidates. Existing raw category bins/colours are unchanged; gaps >12h are not bridged. Maps are genuine **2000×1300 PNG**, intensity **2000×1200**; the workflow independently decodes every PNG and parses every SVG before publishing. The browser viewer reads only the static manifest/images, not GRIB or private APIs; missing model/run/system images never become another chart.

Standalone SVGs are stored losslessly as `.svgz` to keep the shared Pages tree within its budget. The viewer downloads and bounds the actual graphic, decompresses gzip and saves a genuine `.svg` (not a renamed PNG); older raw SVG remains supported. Model/run changes abort pending graphics exports, and malformed/external-resource SVG is rejected. No native weather-grid parsing happens in the browser.

Full AIGEFS field output keeps a shared method definition in `derived.method` and the stable `local-field-l-v1` ID on each path, avoiding thousands of repeated descriptions without changing any numeric point. Public JSON is bounded to 16MB. Each completed member is atomically checkpointed as compact JSON; only complete, exact-run/member/method 41-frame checkpoints may be explicitly reused. `resume_run_id` accepts artifacts only from this repository's completed MAIN scheduled/manual run of the same workflow, not PR/fork runs. Artifacts include those JSON checkpoints and native-unit evidence, never GRIB. This also prevents a final publication-size failure from discarding an hour of verified tracks.

Image viewer: <https://bunnhack.github.io/bunn-ens/ncep-ensembles/>. Actual publication and field-L status are authoritative in its `index.json` (definitions/workflow code alone do not establish that every product is already published). This independent pre-rendered channel does not by itself mark the Vue model-selector integrations complete. NCEP sources require no WindBorne credential and do not bypass the exhausted WM-6 account quota. Both chart workflows serialize their shared Pages deployment and restore **both** chart trees; missing/different cached publications abort rather than deleting the other model's charts. NCEP retains up to two distinct bases/model within 48MiB; WM-6's original chart publication stays intact.

## Cloudflare Pages deployment

The Pages project uses **Advanced Mode** with a GitHub source connection to `BunnHack/bunn-ens` (`main`), build command `npm run build` and output directory `dist`. It was initially created using Direct Upload.

- `public/_worker.js` is copied into `dist/_worker.js` and routes `/api/wnc2` and `/api/wm6` while serving static assets through `env.ASSETS.fetch()`.
- `GET /api/wnc2?model=FNV3P1&cycle=latest` discovers the latest published six-hour run in the previous 72 hours, probes 00/06/12/18Z in descending order, fetches the fixed Google DeepMind WeatherNext source, validates the CSV, and returns JSON metadata plus CSV.
- `cycle=00z|06z|12z|18z` performs an exact-cycle discovery; add `date=YYYY-MM-DD` for an exact historical run. `model=FNV3P1|FNV3P2|WNV3|OPER` is allowlisted. GENC uses `OPER`; for the supplied WNC3 run use `/api/wnc2?model=WNV3&cycle=18z&date=2026-10-16`.
- Cloudflare `fetch` cache is used for upstream WeatherNext CSV responses for 5 minutes. The frontend checks latest every 5 minutes while visible and refreshes on tab visibility.
- `public/data/FNV3P1_2026_10_13T00_00_cyclogenesis.csv` is a downloaded 00Z fallback. The UI labels fallback data as not confirmed latest. Other runs fail instead of silently reusing old data.
- `GET /api/wm6?initialization_time=latest&include_details=true&format=json` proxies WindBorne's WM-6 tropical cyclone list through the Pages Worker. It supports basin filtering and optional unmatched member tracks. Cone fields and polygon features are removed before caching and returning the response. After selecting a cyclone, the app pins the returned `initialization_time` and requests `/api/wm6/{id}?include_members=true`; the detail response supplies the provider's `mean_path`, every `members_path` and member landfalls.
